# Anfitrión operativo del orquestador SQL aislado

Decisión y plan, 2026-10-25. Implementar anfitrión .NET y adaptadores concretos; validación solo offline, sin abrir bases, ejecutar SQL ni SAP. Conservar cambios actuales. Reutilizar orquestador, ejecutor PowerShell, SuiteLoader, monitor y empaquetador.

El anfitrión construye los bindings del orquestador. Implementa revisión/provisión mediante PowerShell instalado invocado en runspace y lanzamiento de la suite mediante proceso hijo restringido. Las decisiones de aprobación y entrega de recursos siguen siendo funciones explícitas del responsable; no se inventan aprobaciones ni se abren conexiones administrativas o del monitor. Review predeterminado no activa adaptadores. Una aprobación del anfitrión vincula plan y hashes de scripts, módulo, runtime, dotnet y archivos de entrada del testhost.

PowerShell se usa mediante reflexión sobre una instalación local aprobada, sin instalar SDK/NuGet ni referencias globales. Código de invocación fijo y parámetros de objeto, nunca concatenación de secretos. Sesión administrativa ya abierta y cinco SecureString solo en memoria. Cancelación solicita Stop del runspace; recursos y bloqueos de archivos permanecen hasta que termine la invocación real.

La suite usa dotnet vstest sobre el assembly congelado, filtro cerrado, sin build/restore ni shell. El hijo recibe entorno construido por lista permitida y únicamente sus cuatro conexiones aprobadas; no hereda credenciales/gates del padre. Salidas de consola se drenan sin persistirlas. Se conserva el Process original para el monitor. Cancelación/Stop solo puede terminar ese proceso propio; no buscar ni matar procesos por PID o nombre. No borrar datos del laboratorio.

Integración necesaria: SuiteLoader admite una raíz explícita de evidencias del hijo, validada con RunId y formato, conservando su ruta anterior cuando no se suministra. Evita depender del directorio efectivo que el runner asigne al testhost. No hay lectura de esa variable durante descubrimiento ni activación de SQL en pruebas offline.

Plan: pruebas rojas; contratos de IO simulable, anfitrión y adapters nativos; raíz explícita con regresiones; pruebas offline y revisión nativa PowerShell solo en modo Review si el runtime local permite; documentación; revisión independiente final; compilación y regresión offline excluyendo SQL/SAP. Integridad no equivale a autenticidad ni cierre global de fase 7.

Ruling de integración tras revisión: dotnet vstest es el runner, no el proceso que escribe RuntimeStart. Se añadió un enlace local previo a conexiones, mediante pipe CurrentUserOnly, nonce aleatorio, RunId, huella del assembly, PID e inicio. El padre captura una sola vez el testhost vivo, comprueba ascendencia Windows y sesión, conserva ese handle y envía ACK antes de permitir avanzar al fixture. No hay búsqueda tardía de procesos por nombre o sustitución de PID. Runner y testhost se esperan por separado, con exit codes separados; el monitor recibe el testhost real. Sin la variable de enlace se conserva la ejecución manual anterior. Se agregaron pruebas puras de desafío/identidad y un enlace local con los procesos de pruebas ya existentes, sin lanzar procesos ni usar SQL.

Resultado de implementación: anfitrión con adaptadores concretos PowerShell/runspace y dotnet/vstest, sin SDK instalado ni aperturas administrativas automáticas. Se verificó nativamente Review de 639 lotes, con SQL0/SAP0; pruebas de puertos simulados y enlace local con procesos de prueba ya existentes. La revisión independiente encontró la confusión runner/testhost; se corrigió mediante desafío local, ascendencia y handle conservado antes de conexiones, con códigos de salida separados. Una primera regresión general detectó además una carrera entre dos temporizadores de limpieza: ahora la espera y Stop comparten el mismo token y las regresiones específicas quedaron verdes. Todas las pruebas nuevas del anfitrión fueron aprobadas en la primera regresión general; la repetición completa final se conserva por separado. No se ejecutó ninguna suite SQL real ni SAP. No se alteraron bases de datos, instalaciones o configuración global.
